晨曦与夕阳分开：原来日出和日落共用一支 `sunset`（#65544c 灰褐）与一套不随小时变化的半球光，「低太阳」只体现为强度低，于是清晨和傍晚看起来是同一种发暗的黄昏。现在按 hour < 12 分成上升与下降两条色路：晨曦天空 #c2877c、夕照天空 #9d5836，太阳色温分别向 #ffd2a6（粉桃）与 #ff9450（橙红）收敛，半球光的上半色（#ffd9cd / #ffb077）跟着走、下半色由 #665044 暖到 #75503a，冷补光从 #a8c7ff 抬到 #86a8ff 且强度从 0.45 退到 0.25（满蓝的补光会把黄金时段平均掉）。低太阳同时压低了光源本体：`sun.position.y` 从 `1 + max(.13,|h|)*6` 改为 `1 + max(.08,|h|)*5.9`，地平线附近从 1.78 m 降到 1.47 m，光更贴平地掠进窗户，影子拉满整块地板而不是午间那种短影。时段文案也跟着改成「晨曦 · DAWN」（< 8.5）与「夕阳 · GOLDEN HOUR」（≥ 16.5）。四时段间接光烘焙本来就是 dawn / dusk 两张，这里只改直射光、天空与补光的配比。

移动端全屏后触摸旋转失效：屏幕上的画布是 `renderer.setSize(innerWidth, innerHeight)` 按像素铺的，而 `resize()` 只挂在 `window.onresize` 上，进入全屏（手机地址栏收起、视口变高）与旋转屏幕这两件事都可能先到、尺寸后到甚至不来，画布就比可视区域短一截——多出来的那条区域上的手指落在 `#app` 背景上，旋转自然没反应。现在 `resize()` 自身幂等（同尺寸直接返回），并在 `fullscreenchange` / `webkitfullscreenchange` / `orientationchange` / `visualViewport.resize` 上重算，且 `settleViewport` 连做三帧（事件里报的尺寸可能还是旧的）。另外 OrbitControls 从画布改绑到满屏的 `#app`（面板是它的兄弟节点，所以点面板永远不会带动房间），配合 CSS 把 `#app` / `canvas` 的 `touch-action` 设为 `none`、`html,body` 加 `overscroll-behavior:none`，手势不再被浏览器的下拉刷新或边缘滑动接管。这里带出一个回归：OrbitControls 会把指针 `setPointerCapture` 到自己的 domElement 上，改绑之后画布上的 `pointerup` 再也不触发，而“点模型互动”正是靠「按下与抬起的位移 < 5px」判定的，于是点模型全失效（手机上表现最明显）——把这对监听器从画布移到与控制器相同的 `#app` 即可，射线换算仍用画布的 `getBoundingClientRect()`（相机投影映射的是那块矩形）。

窗帘并入作息：`devices` 新增 `blinds`（true = 收起 / false = 放下，旧存档缺这个键时用默认的「收起」），作息表里插入两段——06:54 `curtains-up`「拉开窗帘」（排在 06:36「起床」之后，所以是床头灯先亮、窗帘后拉开）与 23:00 `curtains-down`「拉上窗帘」（排在 23:36「准备睡觉」之前，所以是先合上窗帘、再熄台灯），其余白天各段显式写 `blinds: true`，`darkDevices` 里写 `false`，这样从一天中任意时刻刷新进来都不会把窗帘留在夜里那一档。窗帘的动画继续由 `touch-feedback.ts` 拥有（逐帧 damp 百叶窗叶的 y 与 rotation.x），但状态源从模块内的 `blindsOpen` 改成 `state.devices.blinds`，于是点击窗帘与展示模式的驱动是同一条路径，也会随存档一起恢复；`activate()` 的返回文案不变（「百叶窗收起 / 百叶窗放下」）。步骤名会照常进状态行（`23:00 · 拉上窗帘`），所以不必再在 `describeChange` 里报一次窗帘。

墙上挂钟的指针跟房间时刻走：Blender 源里 `INT_clock_wall` 是沿 X 轴的圆盘（x 2.018→1.99、y −1.47、z 2.0），时针与分针是独立的 `ANIM_clock_hour` / `ANIM_clock_minute`（各 12 面，带 ANIM_ 前缀所以自然不进静态合批）。导出物不是 pivot-ready 的：指针的原点落在指针身上某处而不是表盘中心，直接转 `rotation` 会变成指针绕自己打转，而绕钟心转会变成整根指针绕着钟心画圈（长针恰好歪打正着，短针会明显偏离刻度）。现在的做法是三步都用几何自解、不硬编码模型朝向：①每根指针 `attach` 到一个建在钟体包围盒中心的 `PIVOT_clock_hour` / `PIVOT_clock_minute` 组下（`attach` 保持世界变换不变，不会跳位）；②沿指针自身长度把它平移，使它的**基座**（局部包围盒长轴两端里离钟心更近的那一端，换算到世界坐标比较）落在枢轴上，于是它绕表盘中心摆动而不是绕圈；③把模型绘制时的姿态记成 `rest`（用「表盘在钟体前面」的偏移定朝外法线、世界 +Y 当 12 点，算出该姿态相对 12 点的顺时针夹角），转动时用「目标刻度角 − rest」，因此模型画的不是 12:00 也照样读得准。转轴与方向同样由指针最薄的局部轴（表盘法线）换算到枢轴局部坐标系取主导分量得到。分钟手一小时一圈、时针手 12 小时一圈且跟着分钟连续爬行（11:30 时时针停在 11 与 12 之间），时间暂停时也跟着停。这里还踩了一个坑：读几何尺寸时用 `setFromBufferAttribute(geometry.getAttribute('position') as BufferAttribute)` 是错的——Draco/GLTFLoader 给的是交错缓冲（InterleavedBufferAttribute），这个强制转换会算出 NaN 包围盒，接着位移变成 NaN，两根指针会在页面上直接消失。改成先用 `geometry.computeBoundingBox()`（它认识交错缓冲），并给位移加两道闸门（长度有限、落在合理范围、且方向基本在表盘平面内）以及 `rest` / 枢轴位置的有限性检查：量不出来就跳过这根指针——宁可不转，也不能让它消失。

控制面板的移动端自适应：根因是 `.console` 的 `max-width:calc(100% - 32px)` 相对自身计算（父级 .dock 宽度由内容决定），462px 的面板在 390px 手机上实际渲染成 430px 宽并向左溢出到 x=-36，把同一 dock 里的圆环也带出屏幕（只剩 20px 可见）。改成 `calc(100vw - 32px)` 并按视口定宽（手机 = 100vw-24px）后实测回到 12..378；手机上面板改为上下顺序反转（column-reverse）让圆环落在面板下方，避免面板盖住唯一的开合入口；`.console-title` 留在面板框内、只有 `.console-body` 滚动，所以拖动把手与 ⟲ 复位始终可点——这里又踩到一个坑：`.dock.open>.console{display:block}` 的优先级压过 `.console{display:flex}`，面板不是 flex 容器，body 就无法收缩，设置内容会溢出面板底部 428px，改为 `display:flex` 后 body 才在面板内滚动（468px 内滚动 792px 内容）。触屏下开关放大到 42×24、行高 34、面板按钮 38（`@media(pointer:coarse)`），并用 `env(safe-area-inset-bottom)` 让开手机手势条；竖屏与横屏（≤520px 高）分别限高，横屏时面板宽度收敛到 min(440px,60vw)。
